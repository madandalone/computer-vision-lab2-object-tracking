# Лабораторная работа №2. Трекинг плоского объекта на видео

**Дисциплина:** Компьютерное зрение  
**Задача:** отслеживание прямоугольного плоского объекта на видеопоследовательности по ключевым точкам.

Программа позволяет выбрать любой кадр видео и указать четыре угла эталонного объекта. На следующих кадрах она пытается определить положение объекта, построить четырёхугольную рамку и подписать объект.

## 1. Теоретическая база

**Ключевые точки и дескрипторы.** Для поиска объекта применяется SIFT (Scale-Invariant Feature Transform). Алгоритм выделяет характерные точки изображения и вычисляет для них дескрипторы, которые можно сопоставлять между эталоном и текущим кадром. SIFT устойчив к изменению масштаба и повороту в определённых пределах.

**Сопоставление признаков.** Дескрипторы сравниваются с помощью BFMatcher и евклидова расстояния (L2). Для каждой точки ищутся два ближайших соседа, затем применяется тест Лоу (ratio test), уменьшающий число неоднозначных соответствий.

**Гомография и RANSAC.** Для плоского объекта перспективное преобразование между эталоном и кадром приближённо описывается матрицей гомографии $H$ размерности $3\times3$. Алгоритм RANSAC оценивает $H$ по согласованным соответствиям, отбрасывая выбросы. Точки, согласующиеся с найденной моделью, называются *inliers*. Углы эталона преобразуются через $H$, формируя рамку объекта.

**Оптический поток Лукаса–Канаде.** Если на текущем кадре SIFT не смог построить допустимую рамку, используется разреженный оптический поток. Он оценивает перемещение ранее отслеженных точек между соседними кадрами. По сохранившимся соответствиям между эталоном и текущим кадром повторно вычисляется гомография.

## 2. Описание разработанной системы

### Архитектура

- `main.py`: чтение видео, выбор и кэширование ROI, запуск трекера, рисование рамки, сохранение результатов и метрик.
- `tracker.py`: поиск и сопоставление SIFT-признаков, оценка гомографии, резервный трекинг Lucas–Kanade и проверка геометрии.
- `generate_report.py`: формирование настоящего отчёта по CSV и обработанным видео.
- `videos/`: входные видео, включая самостоятельно снятый ролик.
- `results/roi/`: сохранённые координаты четырёх углов и индекс выбранного кадра.
- `results/debug/`: изображения соответствий для анализа проблемных кадров.
- `results/`: размеченные видео, `tracking_metrics.csv` и при наличии `tracking_methods.csv`.

### Алгоритм обработки

1. Пользователь выбирает кадр ползунком и отмечает четыре угла объекта; номер кадра и координаты сохраняются в JSON.
2. Эталон выпрямляется перспективным преобразованием в прямоугольное изображение.
3. На эталоне один раз вычисляются ключевые точки и дескрипторы SIFT.
4. На очередном кадре находятся SIFT-соответствия и оценивается гомография методом RANSAC.
5. Проверяются выпуклость и площадь рамки, допустимость её положения, распределение inliers и ошибка перепроецирования; согласованные точки сохраняются для следующего кадра.
6. Если SIFT не дал допустимой рамки, выполняется Lucas–Kanade по точкам предыдущего кадра, затем повторная оценка гомографии и проверка рамки.
7. Если оба метода не сработали, рамка не рисуется; на следующем кадре выполняется новая попытка обнаружения.
8. Для успешных кадров рисуются четырёхугольник и подпись, а результаты сохраняются в MP4 и CSV.

### Запуск

Требуются Python, `opencv-python` и `numpy`. Запуск из корня проекта:

```bash
python -m pip install opencv-python numpy
python main.py
python generate_report.py
```

Для повторного выбора эталонной области: `python main.py --reselect-roi`. После выбора кадра нажмите Enter, затем отметьте четыре угла объекта и подтвердите Enter; R сбрасывает точки, Esc отменяет выбор.

## 3. Результаты работы и тестирования системы

Обработано **4 видео**, всего **2171 кадров**. Рамка построена на **2099 кадрах (96.7%)**.

Доля обнаружений определяется как число кадров с построенной рамкой, делённое на число обрабатываемых кадров. Эта метрика не равна точности геометрической локализации, поскольку разметка истинных границ объекта отсутствует.

| Видео | Кадров | SIFT | Lucas–Kanade | Обнаружено | Доля обнаружений |
|---|---:|---:|---:|---:|---:|
| `IMG_6514.MOV` | 497 | 459 | 10 | 469 | 94.4% |
| `mona-lisa-blur-extra-credit.avi` | 558 | 320 | 213 | 533 | 95.5% |
| `mona-lisa-blur.avi` | 558 | 337 | 204 | 541 | 97.0% |
| `mona-lisa.avi` | 558 | 352 | 204 | 556 | 99.6% |
| **Итого** | **2171** | **1468** | **631** | **2099** | **96.7%** |

Резервный трекинг Lucas–Kanade обеспечил **631 дополнительных обнаружений** (30.1% от всех обнаружений). В данной реализации метод LK запускается только после неуспешного SIFT.

## 4. Выводы по работе

Реализован алгоритм трекинга плоского объекта на основе ключевых точек SIFT, оценки гомографии методом RANSAC и резервного оптического потока Lucas–Kanade. Система обрабатывает набор видео, позволяет выбирать эталон по четырём углам на произвольном кадре и сохраняет рамки, диагностические изображения и количественные показатели.

На 4 видео получена общая доля обнаружений **96.7%**. Доля обнаружений отражает наличие принятой рамки и не является измерением точности локализации. Качество зависит от текстуры объекта, масштаба, смазывания, числа корректных соответствий и допустимости найденной геометрии.

На самостоятельно снятом видео `IMG_6514.MOV` рамка построена на **469 из 497 кадров (94.4%)**.

Добавление Lucas–Kanade позволило продолжать отслеживание на кадрах, где SIFT не прошёл проверки. Наличие рамки само по себе не гарантирует точности её положения; для количественной оценки ошибки локализации потребовалась бы покадровая разметка эталонных границ.

### Итог последнего улучшения

В последнем эксперименте улучшение геометрической проверки повысило долю обнаружений с 84,7% до 93,6% (2554/2728 кадров). Для `simple_track.avi` результат вырос с 39,3% до 81,7%, а число пропусков с причиной `invalid_geometry` снизилось с 314 до 78. Это сравнение зафиксированных запусков; актуальные показатели в таблице выше берутся из CSV.
